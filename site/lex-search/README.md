# Ҳуқуқий қидирув / Правовой поиск по lex.uz — прототип для демо

Локальная копия действующего законодательства Узбекистана (Конституция, кодексы, законы)
**на узбекском и русском языках** и быстрый поиск по каждой статье. Всё работает на ноутбуке,
без внешних сервисов: Python + SQLite FTS5.

## Где открыть

**https://nasa.cartify.ink/qidiruv/** — работает на сервере как раздел сайта Lex Monitor, на компьютере
ничего запускать не нужно. Как устроено на сервере — в разделе «Сервер» ниже.

По умолчанию интерфейс на узбекском (латиница) и ищет по узбекским текстам. Язык интерфейса
переключается в правом верхнем углу:

| Интерфейс | Запись узбекского текста |
|---|---|
| **Oʻzbekcha** | латиница 1995 года: oʻ, gʻ, sh, ch |
| **Ўзбекча** | кириллица, как в официальных текстах на lex.uz |
| **Özbekça · 2026** | новый латинский алфавит (ЗРУ-1184 от 21.10.2026, вступает в силу 22.04.2027): ö, ğ, ş, ç |
| **Русский** | интерфейс на русском, поиск по русским текстам |

Под строкой поиска выбирается язык документов: узбекские, русские или все.

Что показать:
- **Скорость.** Поиск идёт прямо при наборе, в строке результатов видно время ответа (обычно 1–20 мс).
- **Одинаковый поиск в любой записи.** `меҳнат шартномасини бекор қилиш`, `mehnat shartnomasini bekor qilish`
  и `mehnat şartnomasini bekor qilish` дают одни и те же результаты. Апостроф можно писать как угодно:
  `oʻ`, `o'`, `o‘`, `o’`, а также `ö`.
- **Текст закона в выбранной записи.** Официальный узбекский текст на lex.uz набран кириллицей; латиница
  и новый алфавит получаются транслитерацией на лету, вместе с подсветкой найденных слов.
- **Формы слов.** Узбекский: `fuqarolarning`, `fuqaroning`, `fuqarolar` находят «fuqaro».
  Русский: «трудового договора» находит «трудовой договор», «трудовым договором».
- **Статья по номеру и сокращению кодекса:** `jk 169`, `mk 157`, `konstitutsiya 41-modda`, `ст 169 ук`, `тк 81`.
- **Точная фраза в кавычках:** `"право на собственность"`, `"mehnat taʼtili"`.
- **Мягкий поиск.** Если ни одна статья не содержит всех слов, показываются статьи, где есть все слова, кроме одного.
- **Подсказка про другой язык.** Если на выбранном языке ничего нет или есть только частичные совпадения
  (например, узбекский запрос в русском интерфейсе), появится кнопка «Найдено N на узбекском — показать».
- **Фильтры:** Конституция / Кодексы / Законы, «только действующие».
- **Просмотр статьи.** Справа открывается полный текст с подсветкой, путём «Раздел / Глава», датой редакции,
  комментариями LexUz и кнопками «предыдущая / следующая статья». Ссылка «lex.uz» ведёт точно на эту статью.

Ссылку с запросом можно сохранить заранее:
`https://nasa.cartify.ink/qidiruv/?q=mehnat+shartnomasi&ui=uz-new` или
`https://nasa.cartify.ink/qidiruv/?q=ст+169+ук&ui=ru`.

## Что в базе

```bash
python lex.py stats
```

| Набор | Узбекский | Русский |
|---|---|---|
| Конституция | 1 | 1 |
| Кодексы | 20 | 20 |
| Законы | 541 | 557 |
| **Статей и фрагментов** | **19 181** | **19 171** |

Всего 1140 документов, 38 352 статьи, около 40 млн символов текста. База `data/lex.db` занимает 140 МБ,
сжатый исходный HTML в `data/raw` — 46 МБ. Скачано 21.11.2026.

Акты об изменениях («О внесении изменений…», «…ўзгартириш ва қўшимчалар киритиш тўғрисида / ҳақида»)
не скачиваются: их правки уже есть в текущих редакциях кодексов и законов, а в выдаче они были бы шумом.
Включить их можно флагом `--include-amending`. Тексты на каракалпакском языке в прототип не входят.

## Команды

```bash
python lex.py crawl constitution codes laws --lang uz   # узбекские тексты
python lex.py crawl constitution codes laws             # русские тексты (--lang ru по умолчанию)
python lex.py crawl president government                # акты Президента и Правительства (несколько часов)
python lex.py crawl --ids 6257291 --lang uz             # отдельный документ по номеру из URL lex.uz/docs/<номер>
python lex.py search "mehnat shartnomasini bekor qilish" --lang uz --script new
python lex.py search "срок исковой давности" --lang ru
python lex.py reindex                                   # пересобрать индекс из сохранённого HTML, без запросов к сайту
python lex.py serve --port 8000 --db data/lex.db
```

Краулер бережёт сайт: делает 1 запрос в секунду (`--delay`), повторяет запрос при ошибках и
сохраняет сырой HTML в `data/raw/uz` и `data/raw/ru`. Скачанный документ второй раз не запрашивается.

## Сервер

| Что | Где |
|---|---|
| Адрес | https://nasa.cartify.ink/qidiruv/ |
| Код, база, сырой HTML | `/var/www/nasa.cartify.ink/lex-search` (`data/` принадлежит пользователю `lexsearch`) |
| Сервис | `lex-search.service`: `127.0.0.1:18390`, пользователь `lexsearch`, писать может только в `data/` |
| nginx | блок `location ^~ /qidiruv/` в `/etc/nginx/sites-available/nasa.cartify.ink` (копия блока — `deploy/nginx-qidiruv.conf`) |
| Копия nginx до изменения | `/root/backups/nginx-nasa.cartify.ink.before-qidiruv.*` |

Остальная часть nasa.cartify.ink (Lex Monitor, `/studio/`) не тронута. Если Lex Monitor восстановит свой
nginx-конфиг из `/opt/lex-monitor/backups/restore-prior-site*.sh`, блок `/qidiruv/` пропадёт — его нужно
снова вставить из `deploy/nginx-qidiruv.conf` перед `location / {` и выполнить `nginx -t && systemctl reload nginx`.

Команды на сервере (по SSH под администратором):

```bash
cd /var/www/nasa.cartify.ink/lex-search
systemctl status lex-search                 # состояние; journalctl -u lex-search — журнал
systemctl restart lex-search                # после обновления кода
sudo -u lexsearch .venv/bin/python lex.py stats
sudo -u lexsearch .venv/bin/python lex.py crawl --ids 6257291 --lang uz   # докачать документ
sudo -u lexsearch .venv/bin/python lex.py reindex && systemctl restart lex-search
```

Обновить код с компьютера: скопировать изменённые файлы в `/var/www/nasa.cartify.ink/lex-search/lexuz/`
(`scp lexuz/*.py lexuz/ui.html <сервер>:/var/www/nasa.cartify.ink/lex-search/lexuz/`) и перезапустить сервис.

## Опровержения: Lex Monitor → MODDA → папка выгрузки

1. **Lex Monitor** находит ложное утверждение о законе (категория `inaccurate_claim`): цитата, где сказано, почему неверно, норма.
2. **Мост `lex-refute`** (systemd-таймер раз в 2 минуты) берёт из нашей базы ту же статью на узбекском и русском
   и ставит в очередь MODDA ролик-опровержение: формат «Проверка спорного утверждения», узбекский, 9:16, 2 сцены.
   Одно опровержение на правило, не больше 3 новых роликов в сутки — каждая сцена тратит генерацию Google Flow.
3. **Ноутбук** снимает ролик: сессия Claude Desktop в папке `C:\Users\User\AppData\Local\ModdaBridge\desktop`
   с командой `/loop 2m /modda` делает клипы во Flow, `worker.py` монтирует и отправляет MP4 на сайт.
   Ключ Claude API на сервере для этого не нужен.
4. **Мост** забирает готовое видео и собирает пакет в `data/eksport/<дата>_<правило>_<язык>/`:

   | Файл | Что внутри |
   |---|---|
   | `video.mp4` | ролик-опровержение |
   | `README.md` | объяснение на узбекском и русском: утверждение, где оно было, почему неверно, текст статьи, ссылки на lex.uz с датой редакции |
   | `caption.uz.txt`, `caption.ru.txt` | готовый текст для публикации |
   | `case.json` | всё то же в машинном виде (для Telegram, API), все найденные экземпляры фейка |

   и рядом `<пакет>.zip`.

Папка выгрузки: **https://nasa.cartify.ink/qidiruv/eksport/** — вход по логину и паролю, они есть у владельца сервера;
новый пароль: `lex.py eksport-password --out <файл>`
(затем `chown lexsearch:lexsearch data/eksport.auth`). Страница закрыта, потому что в пакетах — непроверенные
автоматические обвинения конкретных аккаунтов. Перед публикацией ролик и объяснение должен посмотреть юрист.

Настройки моста — строка `Environment=REFUTE_…` в `/etc/systemd/system/lex-refute.service`: категории находок,
языки роликов (`uz`, `ru` или `uz,ru`), число сцен, дневной лимит. Проверить, что мост создал бы, ничего не создавая:

```bash
cd /var/www/nasa.cartify.ink/lex-search
set -a; . /opt/lex-monitor/modda/private/service.env; set +a
.venv/bin/python lex.py refute --dry-run
systemctl list-timers lex-refute.timer; journalctl -u lex-refute -n 20
```

**База команды в MODDA = эта база.** Файл `/opt/lex-monitor/modda/code/law-search.private.json` направляет поиск
студии MODDA («база команды») в `https://nasa.cartify.ink/qidiruv/api/modda`: 38 тыс. статей на двух языках вместо
3 442 демонстрационных выдержек. Если в задании есть ссылка lex.uz и номер статьи (или `lang:uz`), API отдаёт ровно
эту статью на нужном языке. Удалить файл — студия вернётся к своей демонстрационной базе.

## Как устроено

```
lex.py               командная строка
lexuz/fetch.py       HTTP-клиент: пауза, повторы, кэш HTML     ← здесь подключить API lex.uz
lexuz/listing.py     обход списков поиска lex.uz (ASP.NET-пагинация)
lexuz/parse.py       страница документа → метаданные + статьи
lexuz/uzbek.py       узбекский: кириллица ↔ латиница ↔ алфавит 2026, единый ключ, окончания
lexuz/store.py       SQLite: документы, статьи, полнотекстовый индекс FTS5
lexuz/search.py      запрос → FTS5 (морфология, стоп-слова, номера статей, BM25)
lexuz/i18n.py        тексты интерфейса на четырёх вариантах
lexuz/passages.py    выдержки в формате MODDA, сопоставление узбекской и русской версий документа
lexuz/refute.py      мост опровержений: Lex Monitor → MODDA → пакеты выгрузки
lexuz/eksport.py     страница папки выгрузки (пароль, видео, zip)
lexuz/web.py, ui.html  веб-интерфейс
```

- **Единица поиска — статья.** Найденный результат ведёт на конкретную статью, а не на документ
  длиной в сотни страниц. Документы без статей режутся на фрагменты примерно по 3000 символов.
- **Узбекский индекс хранит единый ключ.** Каждое слово приводится к одной записи
  (строчные буквы нового алфавита без апострофов: «oʻzbekiston», «ўзбекистон» и «özbekiston» →
  `özbekiston`). Так же приводится запрос, поэтому запись не влияет на результат.
  Затем отрезаются падежные окончания, притяжательные аффиксы и «-lar»: «shartnomasini» → `şartnoma`.
- **Отображение.** Хранится официальный кириллический текст; латиница и алфавит 2026 строятся при выдаче
  с учётом правил: «е» в начале слова → «ye», «ц» → «s/ts», «ъ» → «ʼ», «сҳ» → «sʼh».
- **Ранжирование BM25** с весами: совпадение в заголовке статьи важнее, чем в тексте.
  Запрос с номером статьи ставит эту статью первой.
- **Метаданные:** дата принятия, номер, вступление в силу, дата текущей редакции,
  список редакций, классификаторы ОКОЗ и ТСЗ, источник опубликования, статус.

Узбекские тексты интерфейса написаны один раз кириллицей и транслитерируются автоматически.
Перед показом стоит попросить носителя языка вычитать их (`lexuz/i18n.py`).

## После демо: переход на API

Когда выдадут API lex.uz, менять нужно только получение данных: `fetch.py` и `listing.py`.
Парсер, индекс, поиск и интерфейс останутся. Через API можно будет получать
новые редакции и держать базу актуальной.

Дальше по возможностям:
- смысловой поиск (векторные эмбеддинги) вместе с полнотекстовым;
- поиск на одном языке с выдачей на другом: узбекский запрос → русская статья и наоборот (связка по номеру документа);
- ответы на вопросы обычным языком со ссылками на статьи (RAG поверх этого индекса);
- OpenSearch/Elasticsearch вместо SQLite, если объём вырастет до всей базы.

Источник данных: lex.uz, Национальная база данных законодательства Республики Узбекистан
(ГУ «НПИЦ „Адолат“» при Минюсте). Официальные тексты — на узбекском языке; русские тексты
на lex.uz — неофициальный перевод.
